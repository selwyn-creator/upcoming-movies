# MovieMeter — Binnenkort screensaver

A full-bleed, auto-cycling "coming soon to cinema" screensaver, built from the
Figma design and seeded with real data from
[moviemeter.nl/bioscoop/binnenkort](https://www.moviemeter.nl/bioscoop/binnenkort).

Open `index.html` in a browser (or serve the folder with any static server —
no server is actually required, everything including the posters is embedded
directly in `data.js`). It's responsive: row layout on desktop and tablet
landscape, stacked poster-above-info on tablet portrait and mobile.

## How it works

Each film is shown for 9 seconds: the blurred background slowly pans, then
the title, release date and plot fade in one after another (matching the
timing from the Figma prototype), before crossfading into the next film.
Click a dot at the bottom, or hover to pause the cycle.

`data.js` is a **snapshot**, not a live feed — see below for keeping it current.

## Keeping it up to date: `npm run refresh`

```bash
npm install       # one-time; also downloads a headless Chromium (~250MB)
npm run refresh    # rewrites data.js with the current top 10 + fresh posters
```

Run this whenever you want the page to reflect what's actually coming soon
(weekly is plenty — the list doesn't change daily). It:

1. Loads `/bioscoop/binnenkort` in a headless browser and reads off the
   current 10 film IDs from the "Aansprekende films" carousel.
2. Downloads each film's poster from MovieMeter's image CDN.
3. Gets each film's title/plot/release date — from the official API if you've
   set `MOVIEMETER_API_KEY` in `config.js`, otherwise by scraping the film's
   own detail page.
4. Regenerates `data.js` in place, sorted by nearest release date.

### Why it needs a headless browser at all

MovieMeter's **HTML pages** sit behind Cloudflare bot-protection — plain
`curl`/`fetch` requests get a 403. Their **poster CDN** and their **official
JSON API** are not behind that wall (verified: both respond normally to a
plain request), so `refresh.js` only pays the "real browser" cost for the one
page that actually needs it — reading the film list off `/bioscoop/binnenkort`
— via [Playwright](https://playwright.dev).

**Heads up, tested honestly:** while building this, step 1 (reading the film
list) worked reliably every time. Step 3's *fallback* path — scraping
individual film detail pages when no API key is set — got rate-limited by
Cloudflare after the first page in my own test runs, even with delays between
requests and a disguised automation fingerprint. This looks like Cloudflare
detecting the automated browser itself (a known hard problem with headless
Chrome), not just request speed, and I deliberately didn't push further into
evasion techniques to get around it. It may well work fine for you on a
different network — but the reliable fix, and the one I'd actually recommend,
is:

### Get a free API key (makes step 3 fully reliable)

1. Register at https://www.moviemeter.nl/site/registerclient (free for
   non-commercial use — keep the "Bron: MovieMeter.nl" credit link in the
   corner, that's their one condition).
2. Paste it into `config.js`:
   ```js
   const MOVIEMETER_API_KEY = "your-key-here";
   ```
3. Re-run `npm run refresh`. With a key, it skips the fragile detail-page
   scrape entirely for any film where the API returns title + plot + date —
   the whole refresh then only touches Cloudflare once, for the listing page.
4. This same key also makes `index.html` itself hydrate fresher data
   client-side on every load, via `api.js` (JSONP, since the API has no CORS
   headers for a plain `fetch()`).

The response field names in `api.js`/`refresh.js` (`plot`, `title`,
`date_cinema`, etc.) follow MovieMeter's documented convention but weren't
verified against a live key while building this — I don't have one. If
hydration silently falls back to scraped/seed data, open your browser's
Network tab (or add a `console.log(apiData)` in `refresh.js`) on one response
and adjust the field names accordingly.

### If you don't want to touch Node/Playwright at all

`data.js` also works exactly as it is, forever — it just won't reflect new
releases. Update it by hand the same way it was originally built: visit
`/bioscoop/binnenkort`, note the film IDs from the "Aansprekende films"
carousel, and grab posters from
`https://www.moviemeter.nl/images/cover/{id rounded down to the nearest 1000}/{id}.jpg`.

## Files

| File | Purpose |
|---|---|
| `index.html` | markup |
| `styles.css` | layout, responsive breakpoints, animations |
| `app.js` | the cycling/reveal engine |
| `data.js` | the 10 films — generated by `refresh.js`, safe to regenerate, don't hand-edit the poster data URIs |
| `api.js` | optional live API hydration in the browser (JSONP) |
| `refresh.js` | regenerates `data.js` from the live site — `npm run refresh` |
| `config.js` | put your API key here (shared by `api.js` and `refresh.js`) |
